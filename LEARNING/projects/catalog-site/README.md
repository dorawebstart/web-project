# Навчальний проєкт: Каталог товарів/послуг

Один сайт-каталог, два способи, як власник наповнює його контентом —
без потреби в класичній адмінці. Ідея з відео: "сайт під ключ", яким
власник керує через звичайну Google Таблицю або через Telegram-бота.

## Архітектура

```
                       ┌──────────────────┐
                       │   frontend/       │   статичний сайт
                       │  (HTML/CSS/JS)    │   (index.html, app.js)
                       └─────────┬─────────┘
                                 │  fetch(...)
              ┌──────────────────┼──────────────────┐
              │                  │                   │
   ┌──────────▼─────────┐ ┌──────▼──────┐  ┌─────────▼─────────┐
   │  data/demo.json     │ │  Google      │  │  telegram-bot/     │
   │  (локальні дані,    │ │  Таблиця     │  │  api_server.py     │
   │  працює одразу)     │ │  (публічна)  │  │  ← bot.py ← ти      │
   └─────────────────────┘ └──────────────┘  └─────────────────────┘
```

Фронтенд один і той самий — він лише питає дані з різних джерел.
Усі джерела повертають однаковий формат:

```json
{
  "name": "Назва",
  "category": "Категорія",
  "price": 5000,
  "description": "Опис",
  "image_url": "https://... або порожньо",
  "available": true
}
```

## Швидкий старт (без жодних налаштувань)

```bash
cd frontend
python3 -m http.server 8080
```

Відкрий `http://localhost:8080` — сайт одразу покаже демо-дані з `data/demo.json`.

## Два варіанти наповнення

| Варіант | Де | Що потрібно |
|---|---|---|
| **Google Таблиця** | [`google-sheets/README.md`](google-sheets/README.md) | Тільки сама таблиця, доступна за посиланням |
| **Telegram-бот** | [`telegram-bot/README.md`](telegram-bot/README.md) | Python, токен бота від @BotFather |

Обидва варіанти підключаються через кнопки прямо на сайті — перемикач
джерела даних угорі сторінки.

## Чому це корисна практика

- **Python:** робота з SQLite (`db.py`), асинхронний Telegram-бот (`bot.py`),
  REST API на Flask (`api_server.py`).
- **Веб:** fetch API, робота з чужим JSON-форматом (gviz-обгортка Google),
  фільтрація й пошук на клієнті, CORS між сайтом і сервером.
- **Архітектура:** один фронтенд — кілька взаємозамінних джерел даних.
  Це той самий принцип, що в реальних застосунках (dev/staging/prod бекенди).
